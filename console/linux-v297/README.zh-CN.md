# Microduck Console Studio V297 测试版（Beta）

此包先供测试，尚未发布到仓库。请确认本次修复正常后再发布。

## 本次修复

切换标定或运动模式时，缺少 IMU 或某颗舵机，旧脚本会占着管理锁等待最长 60 秒，导致测试和编号入口一起被锁住。本版收到明确的硬件初始化等待状态后，及时结束被动等待、释放管理锁，保留具体设备的中文提示和原始错误。机器人控制服务是否就绪，仍以真实反馈为准。

可随后从左侧进入测试或编号：入口沿用原来的停止服务、确认串口释放、建立测试会话流程。不会因缺 IMU、缺舵机而要求先完成整链初始化。

本次更换中控即可，无需升级固件或重刷 TF 卡。随包固件、维护测试组件、模型与 Policy 与 V296 完全相同，原生运动固件仍为 control.102。

## 启动

- Windows：完整解压，安装 Python 3 后双击 `start.cmd`。
- macOS：完整解压，安装 Python 3 后运行 `start.command`；也可在目录内执行 `python3 console.py --dashboard --feetech --open`。
- Linux：在解压目录执行 `python3 console.py --dashboard --feetech --open`。

先显示准备页，连接 SSH 后按实际状态引导；也可从左侧选择测试、编号、标定或运动模式。日常运动先回 HOME，再进入保持；卸力和叫声可独立使用。

## 本次请重点测试

1. 不接 IMU 切到标定，出现明确中文原因后，能进入测试和编号，不再等旧的 60 秒就绪超时。

3. 完整机器人正常进入标定、运动；标定不足时仍有明确提示；切换不重载页面，不自动 HOME 或启动策略。
