## 3. 统一契约（所有策略可互换的前提）

**观测 61 维**（顺序固定）：

| 段 | 内容 | 维度 |
|---|---|---:|
| 0–2 | 躯干角速度（IMU 机体系）| 3 |
| 3–5 | 重力投影（站立时 z ≈ −1）| 3 |
| 6–19 | 关节角（相对 HOME，rad）| 14 |
| 20–33 | 关节角速度（rad/s）| 14 |
| 34–47 | **上一步动作 = 网络裸输出**（不乘 scale、不加 HOME）| 14 |
| 48–50 | 速度指令 `[vx, vy, wz]` | 3 |
| 51–54 | 头部姿态指令 | 4 |
| 55–60 | 身体姿态指令 | 6 |

**动作 14 维**：关节目标角，语义是**相对 `default_joint_pos` 的偏移**（`scale=1.0`）。
**归一化烘焙在 ONNX 内部**（`Sub`+`Div` 各一次）。

**14 个策略关节（固定顺序）**：
`left_hip_yaw, left_hip_roll, left_hip_pitch, left_knee, left_ankle,
neck_pitch, head_pitch, head_yaw, head_roll,
right_hip_yaw, right_hip_roll, right_hip_pitch, right_knee, right_ankle`

**训练 HOME**（必须与固件要求一致，容差 0.000501 rad）：
```
[ 0.000, -0.087, -0.458, -0.005, +0.453, +0.349, +0.349, 0.000, 0.000,
  0.000, +0.087, +0.458, +0.005, -0.453 ]
```

**关节正方向（HOME 时的世界轴，右手法则）**：左右**不都镜像**——
`hip_roll` 与 `hip_yaw` 左右**同向**，`hip_pitch`/`knee`/`ankle` **镜像**。
实机 `direction` 必须复现这一点。

## 5. 部署现状

模型在板上是**目录**（不是单文件）：

```
/opt/robot/feetech-ft5-r5/models/<sha256(policy.onnx)[:32]>/
    policy.onnx
    deployment-contract.json   ← 必须与 ONNX 图内元数据逐字节一致
    manifest.json              ← onnx_sha256 + task
    training-request.json      ← 只检查存在
```

当前生效（`/etc/robot/feetech-ft5/robotd.toml` 的 `[policy]`）：

| 槽位 | 模型 | 来源 |
|---|---|---|
| `walk` | `models/9f4774d02832…/`（walk_all）| 自训 |
| `sitstand` | `models/3942213bc1c5…/` | 自训 |
| `ground_pick` | `models/3a3a61d8fd3a…/` | 自训 |
| `kick_right` | `models/d0ea8cd0fe41…/` | 自训 |
| `roulade` | `models/8472981cf259…/` | 自训 |
| `kick_left` | 随包 | 作者 |
| `stand` | `"none"` | — |

**更新方法**：`scripts/push_policy.py --onnx <新策略> --template <已部署模型id>`，

## 6. 已查明的问题

| # | 结论 | 证据 |
|---|---|---|
| **1** | **实机"走 20 秒就倒" = 电源接触面接触不良** | 修好后 **walk_all 连续走 1 分钟正常**。此前表现为负载一大就掉压 → 舵机掉扭矩 → 累积到倒 |
| 2 | **摩擦不是摔倒原因** | 摩擦阶梯 μ=0.4/0.7/1.3/1.8/2.5，全部 0% 摔倒，速度变化 <5% |
| 3 | **地形不是摔倒原因（仿真内）** | walk_all 在平地/不平/斜坡均 0% 摔倒；harsh 与之相当 |
| 4 | **+13 g 背板加固不需要重训** | 质量随机化带宽 ±2.5%（≈±21 g），13 g = 1.56%，**在训练分布内** |
| 5 | 慢速转向（0.3 rad/s）学不会 | 所有策略该桶 ≈0.02–0.05，判断为步态层物理限制 |
| 6 | **实机 10/15 关节的 (raw, zero, angle) 不自洽** | 从遥测反推零点，`-1`/`+1` 都推不出标定值。**尚未解决**，可能是标定与运行时的基准不一致 |

## 8. 关键经验（踩过的坑）

1. **奖励曲线会骗人。** 出现过"奖励 127 但站着不动"、"日志恢复率 0.002 但实测 100%"。只有实测算数。
2. **换执行器 = 换问题。** XL330 调好的配方在 HD-1910 上会掉进"站着不动"的局部最优。
3. **改重置分布比调权重有效。** 仰面姿态出现概率 0 → 20%，仰面恢复率 0% → 100%。
4. **门控切换不如单策略。** 同一套验收脚本：单策略恢复 100%，门控合并 67%。
5. **只钉一个命令缓冲不够。** 观测读的是 `term.command`（世界系），只写 `vel_command_b` 会让策略原地站着。
6. **改 TOML 要用整串替换。** 按行重建曾把整份配置插坏，`robotd` 起不来。
